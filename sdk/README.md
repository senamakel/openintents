# SDKs

| Path | Package | Registry |
| --- | --- | --- |
| [`typescript/`](typescript) | `@tinyhumansai/openintents` (SDK + `openintents` CLI) | npm |
| [`python/`](python) | `openintents` (sync + async) | PyPI |
| [`rust/`](rust) | `openintents` (async; CLI behind `--features cli`) | crates.io |
| [`skill/openintents/`](skill/openintents) | Agent skill (`SKILL.md`) | |
| [`plugin-claude/`](plugin-claude) | Claude Code plugin (MCP server + skill) | this repo's marketplace |
| [`examples/`](examples) | One runnable example per language | |

All three SDKs implement the same surface, generated by hand from
[`../spec/openapi.yaml`](../spec/openapi.yaml). Every create (intents,
customers, top-ups, sessions), `cancel`, session `release` and session
command sends an `Idempotency-Key`, so a retry never runs anything twice;
making a profile is idempotent by itself. Intents can be bought for, and
listed by, a `customer`. Event streams follow a timeline over Server-Sent
Events: they resume after a dropped connection with `Last-Event-ID`, and end
when the API answers `204` (the timeline is over).

| Operation | TypeScript | Python | Rust |
| --- | --- | --- | --- |
| Create | `intents.create` | `intents.create` | `create_intent` |
| Retrieve | `intents.get` | `intents.get` | `get_intent` |
| List / all pages | `intents.list` / `listAll` | `intents.list` / `list_all` | `list_intents` |
| Cancel | `intents.cancel` | `intents.cancel` | `cancel_intent` |
| Wait | `intents.wait` | `intents.wait` | `wait` |
| Intent events: page / live stream | `intents.listEvents` / `streamEvents` | `intents.list_events` / `stream_events` | `list_intent_events` / `stream_intent_events` |
| Balance (a customer's) | `balance.get({ customer })` | `balance.get(customer=)` | `balance` / `balance_for` |
| Customers: create, retrieve, update | `customers.create` / `get` / `update` | `customers.create` / `get` / `update` | `create_customer` / `get_customer` / `update_customer` |
| Customers: list / all pages | `customers.list` / `listAll` | `customers.list` / `list_all` | `list_customers` |
| Top-ups: create, retrieve | `topups.create` / `get` | `topups.create` / `get` | `create_topup` / `get_topup` |
| Profiles: create, retrieve, forget | `profiles.create` / `get` / `forget` | `profiles.create` / `get` / `forget` | `create_profile` / `get_profile` / `forget_profile` |
| Profiles: list / all pages | `profiles.list` / `listAll` | `profiles.list` / `list_all` | `list_profiles` |
| Sessions: open, retrieve, release | `sessions.create` / `get` / `release` | `sessions.create` / `get` / `release` | `create_session` / `get_session` / `release_session` |
| Sessions: list / all pages | `sessions.list` / `listAll` | `sessions.list` / `list_all` | `list_sessions` |
| Session commands: run, retrieve | `sessions.runCommand` / `getCommand` | `sessions.run_command` / `get_command` | `run_session_command` / `get_session_command` |
| Session screenshot (JPEG bytes) | `sessions.screenshot` | `sessions.screenshot` | `session_screenshot` |
| Session events: page / live stream | `sessions.listEvents` / `streamEvents` | `sessions.list_events` / `stream_events` | `list_session_events` / `stream_session_events` |
| Errors | `OpenIntentsError` | `OpenIntentsError` | `Error::Api` |
| Webhooks (intent and session events) | `verifyWebhook` | `verify_webhook` | `webhooks::verify_webhook` |

Errors carry the API's `status`, `type` (`kind` in Rust), `code`, `param` and,
with `profile_busy`, the `lease` that says what holds the profile.

Versions move together; `node sdk/bump-versions.mjs <patch|minor|major>` bumps
all of them.
